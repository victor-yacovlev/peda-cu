# Проверенные грабли (QEMU × GDB × gcc × RISC-V)

Всё ниже — установлено экспериментально на стенде Debian 13 / qemu-riscv64
10.0.13 / gdb-multiarch 16.3 / gcc 14.2. Экономит часы отладки.

## Python API GDB

- `gdb.selected_target()` **не существует** (AttributeError в GDB 16.3),
  несмотря на встречающиеся советы. Правильный детект соединения:
  `gdb.selected_inferior().connection` → `gdb.RemoteTargetConnection`
  (доступно с GDB 12).
- `gdb.selected_inferior().pid` под qemu-user = **PID хост-процесса qemu**
  (не «1» и не гостевый PID). Это делает корректным локальное чтение
  `/proc/<pid>/maps` (гостевые адреса = хостовые, трансляции нет).
- Многострочный python через серию `-ex 'python' ... -ex 'end'` **не работает**:
  каждый `-ex` — отдельная строка. Пишите python в отдельный файл и
  `source file.py`.
- Python `sys.stdout` внутри GDB завёрнут в GDB-канал: подчиняется
  `set logging redirect on` — если логирование осталось включённым,
  python-print тоже уходит в файл.

## GDB: форматы вывода

- `info program` на remote: маркер `Remote debugging using :PORT`
  (подстроки `serial line` из старых GDB больше нет).
- `info proc mappings`: современный формат с колонками
  `Start Addr End Addr Size Offset Perms File`; в старых GDB колонок
  Perms/File нет. Работает под qemu-user (qemu ≥ 5, gdb ≥ 9 пара-dependent —
  проверяйте на своём стенде).
- `remote get` (vFile): qemu-gdbstub отклоняет произвольные пути —
  `Remote I/O error: Permission denied`. Работает только с настоящим gdbserver.
- `info args`: GDB 16 печатает **по одному аргументу на строку**
  (`a = 1\nb = 2`), старые — одной строкой через запятые.
- `info registers <reg>` на RISC-V печатает 3 колонки: `имя hex dec` —
  парсить вторую; значения **беззнаковые** (для знаковых сравнений делать
  sign-extension самостоятельно).
- `set logging on/off` deprecated в GDB 16 — Warning-шум в начале сессии
  peda нормален.

## binutils / дизасм RISC-V

- Мнемоника и операнды разделены **TAB**, а не пробелом (`bge\ta5,a4,...`).
  В regex использовать `\s` / `\S`, не `[ ]`. `str.split()` без аргументов
  TAB обрабатывает.
- Offsets ветвлений могут быть **bare hex** без `0x` (`104ee <sum6+58>`)
  и с `0x` (`0x1052e <main+68>`) — оба варианта надо уметь.
- `jr`/`jalr`: цель — регистр (`jr ra`), у `jalr rd,rs1,imm` цель в rs1
  (второй операнд), а не последний операнд.
- Адрес в `disassemble main` до запуска PIE-бинаря — **файловый offset**
  (0x11ae), не рантайм-адрес: breakpoint по нему не вставится
  («Cannot insert breakpoint»). Сначала `start`/`target remote`, потом
  ставить bp по дизасму.

## gcc -O0 на RISC-V: пролог функций с аргументами

Компилятор **ротирует и раскладывает аргументы по стеку**:

```
mv a6,a0        # сохранить a
mv a0,a1        # сдвиг
...
mv a5,a6
sw a5,-20(s0)   # разложить по стеку
```

Следствие: на `break func` (GDB останавливается после пролога) регистры
a0..a5 уже **перетасованы** — читать аргументы из регистров нельзя, брать из
DWARF (`info args`). На инструкции вызова (`jal`) регистры ещё корректны.
На x86-64 такой проблемы нет (пролог не портит arg-регистры).

## QEMU-user

- После `detach` в gdb qemu **возобновляет и доводит программу до конца** —
  повторное подключение к тому же порту невозможно. Один сценарий — один
  запуск qemu (все тестовые скрипты так делают).
- `run` в gdb на remote-таргете не поддерживается — использовать `continue`
  (процесс уже остановлен на entry). `peda start` делает это сам.
- static-pie загружается qemu с базы 0x10000 (не 0x5555...).

## PEDA-специфика

- `hook-stop` → `peda context` на **каждой** остановке: batch-вывод тестов
  интерливится контекстом; крэш в context каскадно роняет UX всей сессии.
- Исторический баг (исправлен): `@msg.bufferize` не делал flush при
  исключении → после первого падения команды весь вывод peda исчезал
  (счётчик buffering утекал). Регрессия покрыта
  `tests/test_lib_utils.py::TestMessageBufferize`.
- В теле `get_vmmap` локальная переменная `os = self.getos()` затеняет модуль
  `os` — во вложенных функциях (`_get_allmaps_linux` и др.) нельзя писать
  `os.path.*`.
- peda сохраняет `peda-session-<binary>.txt` в cwd gdb — запускать из tmp.
- `gdb -batch` + серия `-ex` — самый надёжный способ автоматизации;
  exit-код gdb не отражает падения python-тестов — парсить вывод.
- `reset_cache()` сбрасывает `@memoized` (включая методы инстанса `peda`),
  вызывается автоматически на каждую peda-команду, но НЕ внутри python-блоков.

## Цвета

- peda-вывод содержит ANSI-коды **даже при редиректе в файл** (colorize не
  проверяет tty). Паттерны grep для логов должны это переживать
  (например `'A0 .*: 0x'`, а не `'^A0:'`).
